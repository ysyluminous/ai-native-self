# 模型包契约（pack contract）· v0.1

> 这个仓库是**操作系统**，不是某个人的思想。思维内容全部以模型包（pack）形式插拔。
> 你可以用维护者发布的包，也可以自己建包，还可以只用 `packs/self/`（你自己的编译产物）。
> 内核与包的关系：**内核给裁判规则，包给裁判结论。冲突时内核结构件优先**（`kernel/principles.md` 末节）。

## 什么是包

一个包 = 一套**可运行**的思维框架，不是语录合集。它必须能被 agent 用来分析新问题，
并且知道自己**在哪些问题上是无效的**。

**包不是独立 skill**，而是本 skill 读取的数据文件（放在用户的语料仓库 `packs/` 下）。
这样做的三个好处：内核 `git pull` 升级不影响包；任何 runtime 无需为每个人物单独装 skill；
包与语料同仓库、同备份、同一次 `git log` 可审计。

```
packs/<slug>/
├── pack.md          # 唯一必需文件：契约要求的全部内容
├── sources/         # 可选：材料清单与出处指针（不放受版权限制的原文全文）
└── CHANGELOG.md     # 可选：包版本变更
```

`slug` 短、小写、连字符：`munger`、`bayes`、`nan-huaijin`、`ni-haixia`、`alan`、`self`。

## front matter（必填）

```yaml
---
slug: munger
name: Charlie Munger
kind: person|school|method|tool|self
version: 0.1.0
maintained-by: official|community|self        # 谁在维护
window: 1994-2023                               # 取材时间窗
evidence: A|B|C                                 # 本包能承重的最高证据等级
evidence-ratio: {A: 12, B: 5, C: 2}             # 各级材料条数
license: MIT                                    # 本包原创部分
source-of-truth: 本包只含蒸馏结论；原文出处见 sources/
trigger: ["用芒格的视角", "芒格会怎么看", " Munger perspective"]
auto-trigger: false                             # 必须 false
domain-fit: [decision, investing, cognition]    # 适用领域
domain-na: [medicine, law, engineering]         # 明确无效领域
conflicts: [{pack: <slug>, on: "<议题>", why: "<一句>"}]
guardrails: [medical|legal|financial|spiritual] # 需要的额外护栏
---
```

`evidence: C` 的包自动成为 **low-evidence 包**：可用于表达与联想，**不得进入决策顾问团**，
不得写入任何 `verified: true` 的断言。

**等级怎么判，包必须自己写明**（同一字母在两类材料上含义不同）：
- `person|school` 类：A = 纸本/原始录音逐字可核；B = 第三方全文转载，内容可核而页码不可核；C = 二手解读。
- `method|tool` 类：A = **引文条目可定位**（作者/年/刊/卷/页或 DOI 已在 ≥2 处独立文献列表一致）——
  注意这核对的是"引文存在"，**不等于原文逐字已读**；公式与页码要对外引用仍需取原件。
  把这两种 A 混为一谈，是本契约最容易被骗过的一处（`kernel/principles.md` #11）。

## 必备章节（缺任一章节不许入库）

1. **一句话总纲** — 这个框架的压缩形态。
2. **心智模型 3-9 个**，每个四件套：
   - 一句话（框架本身）
   - 证据（带 A/B/C 等级与出处；`kind: self` 的包用记录 id）
   - 应用条件（什么样的问题该用它）
   - **失效条件与反例**（它会把哪类问题答错）— 没有这条的模型直接拒收
3. **决策启发式 5-15 条** — 每条给"什么时候不按它做更好"。
4. **表达 DNA**（可选，仅在支持角色扮演时需要）— 句式/词汇/论证弧/禁止漂移的腔调。
5. **诚实边界**（必需，不许写成免责声明套话）：
   - 利益立场（卖什么、代言什么、有什么商业动机）
   - 时代与领域局限（哪些结论不能外推到哪）
   - 二创污染（哪些"名言"其实是别人编的）
   - 未证实数据（哪些数字只能作"XX 说"引用）
6. **双模式**：
   - 模式一 分析者（默认）：用框架分析，不冒充本人；首次回答声明取材窗口，之后不重复。
   - 模式二 扮演：仅当用户显式点名才进入，进入时一次性免责，保留"正文+适用条件+一次自我校正"，
     用户说"退出/切回正常"立即回到分析者模式。
   - `kind: school|method|tool|self` 的包只实现模式一。
7. **冲突表 + 裁决顺序** — 与已装其他包在哪些议题上会给出相反建议，分歧的根源假设是什么；
   并写出**顾问团该按什么顺序决定谁先说话**（只有分歧表没有裁决顺序的包，顾问团会当场卡住）。
8. **材料清单**（`sources/` 或本节内列出）— 每条：来源、时间、等级、可核验路径。

## 建包流程（用户说「给 XXX 建一个包」时）

1. **声明材料等级**：agent 先回答"我能拿到什么等级的材料、缺什么"，并列出需要用户提供的
   （如：书的具体章节、演讲原文、视频链接）。只有二手摘要时，明确告知将建成 low-evidence 包。
2. 复制 `packs/_template/pack.md` → `packs/<slug>/pack.md`，填 front matter。
3. 抽模型：每条必须能指回具体出处；**同一出处堆出的多条要合并**。
4. 补失效条件与反例（这一步最容易偷懒，也最值钱）。
5. 过 lint（下一节）：结构项可机器查 —— `node scripts/lint-packs.mjs`（含阳性对照 `--selftest`）；
   语义项仍需 AI/人判。登记 `registry.md`，写 `version: 0.1.0`。
6. 首次使用前跑一次"压力测试"：挑 3 个该框架**明显不适用**的问题，确认它会说"我无效"而不是硬答。

## lint 清单（AI 自检，逐项回答 pass/fail）

> `scripts/lint-packs.mjs` 机器可查的是**结构子集**：字段齐全、`auto-trigger: false`、
> `domain-na`/`domain-fit`/`trigger` 非空、8 个必备章节、四件套数量与模型数一致、启发式条数、
> 压力测试 ≥3 问、lint 表 12 行且无 fail、有冲突必有裁决顺序、`kind: method|tool|self|school` 不得有扮演模式、
> 以及 **registry ↔ 磁盘一致**（版本/kind/证据等级三列对齐）。
> 下面第 5-8 与 12 项是语义判断，脚本查不了 —— **不要因为脚本绿了就以为包合格了**。
> 脚本自带阳性对照（`--selftest`：故意破坏 4 处，必须报出 4 处；原文必须全 pass）。

1. front matter 必填字段齐全，`auto-trigger: false`。
2. 每个模型都有四件套，失效条件不是"仅供参考"这种空话。
3. 每条证据有等级与出处；无出处断言为 0。
4. `domain-na` 非空（一个说自己哪里无效的包才可信）。
5. 未证实数字全部标 `verified: false` 或降级为"XX 说"。
6. 无群体化断言（"所有女人/所有 X 都…"）作为事实陈述。
7. 无造神表述（把复杂成功简化为单一原因，违反 `kernel/principles.md` #11 与多变量归因）。
8. 版权：`sources/` 不含大段他人受版权保护原文（≤ 少量合理引用的短句）。
9. `guardrails` 覆盖了包的领域风险（见下节）。
10. 冲突表非空（或写明"当前无其他已装包"），并给出**裁决顺序**。
11. 压力测试记录（3 个域外问题）在 `pack.md` 末尾。
12. 包不得包含把用户语料外发到第三方（embedding/SaaS/云端）的任何要求。

## 特殊领域的强制护栏

某些类别的思想**天然越界**，包必须内置对应护栏，否则拒收：

- **医学/传统医学类**（如中医、食疗、训练流派）：只做"思路与观察框架"，
  **不得给出诊断、处方、剂量、停药建议**；不得替代就医；出现急症信号时中止框架套用并建议专业帮助。
  所有疗效断言按 `evidence` 分级，且明确标注证据类型（个案/经验体系/临床研究）。
- **修行/玄学/宗教类**：不可证伪的主张一律记 `kind: preference` 或 `metaphysical`，
  不得进入 `verified: true` 的断言、不得作为决策的事实前提；可以讨论其心理与行为效果。
- **投资/加密类**：必须披露利益立场；不得承诺收益；单笔仓位与买卖点不是框架能回答的问题，
  只能给"最坏值 + 可承受性"检查（`kernel/principles.md` #5）。
- **两性与社交类**：禁止群体化断言与敌我叙事；不从个案推整体。

## registry.md 格式

```markdown
| slug | kind | version | evidence | domain-fit | 维护 | 状态 |
|---|---|---|---|---|---|---|
```
`状态`: stable / experimental / low-evidence / deprecated。deprecated 的包保留但不进顾问团。

## 版本与引用

- 包走 semver；破坏性变更（删模型、改结论）必须升 minor 以上并在包 CHANGELOG 写明。
- 语料里引用包时用 `refs: ["pack:<slug>@<version>"]`。已归档记录保存当时的版本，
  **包升级不改写历史**——你需要在下次月审里主动对比新旧版本。
