# 进化协议 · 评估 → 改进 → 测试 → 保留或回滚

> 一个只能向前转的棘轮：**只保留有改进的改动，退步一律干净回滚。**
> 思路来自 [darwin-skill](https://github.com/alchaincyf/darwin-skill)（MIT，受 Karpathy autoresearch 启发）
> 与微软研究院 SkillLens / SkillOpt 的 validation-gated 框架。

这个项目有两个资产，各有一套评测：

| 资产 | 评什么 | 手段 |
|---|---|---|
| 内核（本仓库） | 方法写得清不清楚、能不能跑、有没有护栏 | `node scripts/score.mjs`（九维结构分，0–100） |
| 语料（你的私有仓库） | 数据干不干净、引用有没有断、索引新不新 | 下面「语料体检」清单 |

**结构分不等于效果分。** `score.mjs` 只做静态检查；方法好不好用，只能在 `examples/` 上真跑一遍看输出。

## 九维结构分

| 维度 | 权重 | 查什么 |
|---|---|---|
| 可执行具体性 | 15 | 模糊措辞（建议 / 可以考虑 / 视情况而定 / 尽量）越少越高 |
| 结构完整性 | 15 | SKILL 头部、四条内核规则、八个模板是否齐 |
| 失败模式编码 | 12 | `kernel/principles.md` 里失效条件与反例的密度 |
| 高风险黑名单 | 10 | 破坏性操作是否明文列禁（`reset --hard`、`--force`、推公开库、写密码） |
| 可验证性 | 12 | `init.mjs`、`lint-packs.mjs`、`score.mjs`、`examples/` 在不在 |
| 模板与契约一致 | 10 | 每个模板都有 `type:`，与 `record-types.md` 对得上 |
| 隐私护栏 | 10 | 三级隐私定义 + 独立的 `PRIVACY.md` |
| 无个人数据 | 8 | 扫描邮箱、内网 IP、本机路径、连接串、令牌（代码块内的示例不算） |
| 文档可达 | 8 | README 讲清安装与许可证，站内链接不悬空 |

权重是调过的，不是神圣比例；改权重必须同时改这一页和 `score.mjs`，否则下一轮评分不可比。

## 五个阶段

**Phase 1 · 基线**
跑 `node scripts/score.mjs`，记下总分和每一维。找**加权缺口最大**的那一维：
`加权缺口 = 权重 × (满分 − 当前) / 满分`。不要挑权重最低的那项来刷分。

**Phase 2 · 单维改进**
一轮**只改一个维度**。改完 `git commit` 一个独立提交，能单独回滚。

**Phase 3 · 测试**
```bash
node scripts/score.mjs                     # 结构分
node scripts/init.mjs /tmp/demo --no-git   # 冒烟：脚手架还能生成干净仓库
node scripts/lint-packs.mjs <你的语料仓库>        # 包契约（示例包故意不过，看它报哪几项）
```
三项有一项挂，本轮作废。

**Phase 4 · 独立评分**
评分不能自己改自己评。换一个 agent / 换一个模型，只给它「改动前后两份文件 + 评分标准」，
让它独立打分。同一轮里改的人和评分的人不许是同一个会话。

**Phase 5 · 保留或回滚**
- 新分 > 旧分 → 保留，基线前进
- 新分 ≤ 旧分 → `git revert <commit>`（**不许** `git reset --hard`）
- 单轮涨幅 < 1 分 → 停手。继续磨只是为了凑分，是在堆冗余

改完给人看 diff 与分数变化，再决定要不要进下一轮。

## 反例黑名单

1. 同一个会话又改又评（LLM 自评准确率约一半，等于没评）
2. 用 `git reset --hard` 当回滚手段
3. 为凑分堆冗余段落
4. 一轮内改多个维度（改动不可归因）
5. 跳过 `examples/` 实测直接宣布改进
6. 把权重改高来提分
7. 静默跳过失败项
8. 把真实个人数据写进 `examples/` 换测试覆盖

## 语料体检（私有仓库那侧）

每次大改后跑一遍，四项全过才算干净：

```bash
node scripts/loop.mjs                       # 索引与数据源通断
node scripts/search.mjs "随便一个词" --limit 3 # 检索还能命中
git status --porcelain                      # 没有意外改动
```

另外人工核对三件（脚本不判断）：

- 新写的记录有没有 front matter，字段是否按 `record-types.md`
- `refs` 指向的块是否真实存在（断链比没写更糟）
- `priv: secret` 的内容有没有误进可提交目录
