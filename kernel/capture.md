# 内核 · 采集协议（capture）

> 目标：让一个从没做过笔记的人在**第 30 天还在记录**。所有设计服从这个目标。

## 20 秒规则

一次倾倒超过 20 秒，就是这套系统的缺陷，不是用户的缺陷。
- 不追问细节。缺字段就留空，归档时由 AI 补 `待补：…` 一行提示，**最多提示一次**。
- 不要求选分类、不要求打 tag、不要求填模板。分类是 AI 的活。
- 不做修辞、不做纠错、不做总结性提问（"所以你的感悟是什么"= 禁止）。

## 单一入口

**写入只走一个入口**：`scripts/capture.mjs`（内核提供，零依赖）。它负责算 id、选分片、
隐私路由、追加块，并重建派生索引。手写 front matter 往 inbox 里塞是常见错误来源（id 撞车、
secret 漏进 git），所以入口收敛成一个。

分片规则：**按月 × 工具**，检索按 `inbox/*.md` 一视同仁。

```
inbox/2026-11.md               # 单工具/agent 手写（默认）
inbox/2026-11.cursor.md        # 多工具并发，一个工具一个分片，互不覆盖
inbox/2026-H2.md               # 旧库的半年一文件：继续被识别，不迁移、不重排
```

追加到文件末尾，一条一个块，块首是 front matter。
**永不重写、重排、删除历史块**；写错了就追加一条更正块并 `refs` 原块。
理由：历史块的完整性就是证据等级的一部分。

`--priv secret` 由 capture 直接路由进 `secret/`，其它目录只留指针块——
因为 `.gitignore` 只排除整个 `secret/` 目录（见「隐私分级」）。

## 会话写回义务（chat-writeback，AI 原生会话专用）

**目标是"避免遗忘"：任何没被写回的事件日志，等于这个结论从未发生过，下次会话必然重做。**

1. **每次会话结束前**，AI 必须把本次的：关键提问、自己的判断与结论（含被用户否决的版本）、
   落盘动作清单、**未决事项（待办遗留）**，以 e 编号块追加进当期 `inbox/` 文件（块首 front matter，
   `refs` 指向产生它的实体/工件）。**写入用 `scripts/capture.mjs`**，不要手拼 front matter。
2. **重要思考不需要等用户开口**：会话过程中一旦 AI 做出"会影响后续行为"的判定
   （定稿/边界/车道/铁规/术语/命名约定），当场写回，不等收尾——防止会话中断丢失。
3. **会话冷启动顺序**：`目录.md`（分域导航）→ 相关分域旗舰 → `scripts/recall.mjs "上次定过什么"`
   → `inbox/` 最近 3 块 → 干活。缺了这步就接不上上一次的上下文，等于遗忘。
4. **写回≠改写**：结论后来变了，追加新块并 `refs` 旧块（如新结论推翻旧结论，
   标 `supersede: [[e-旧]]`），历史永远不动。
5. 写回不宜超过会话总轮数的体量；一句话判定的归 e 块，大块产出的直接建完工件文件再在 e 块里 `refs`。

## 8 个槽位（slot）

每天愿意填几个就填几个，一个也行。`slot` 字段用下列值：

| slot | 提示语 | 为什么存在 |
|---|---|---|
| `changed` | 今天什么变了（外部事实） | 世界发生了什么，不是我怎么想 |
| `decided` | 今天决定了什么（含放弃的决定） | 决策是最可复利的记录 |
| `misjudged` | 我今天判断错了什么 | 唯一能直接提升认知的槽位 |
| `avoided` | 我回避了什么 | 回避是行为的最强信号，通常不会出现在任何总结里 |
| `body` | 身体 + 一个数字（睡几小时/体重/支出） | 地基；数字进 metrics |
| `learned` | 今天学到的一句话（带来源） | 知识边界的可测量增量 |
| `next` | 明天唯一动作 | 把记录接到执行 |
| `free` | 自由倾倒 | 情绪、灵感、无结构内容 |

**冷启动指令**（AI 在用户说"不知道记什么"时使用，一次只问一个）：
> 今天有没有一件事，是你原本预计会不同地发生的？

## 多通道

任何通道最终都落成一条 Event + 可选原件：
- **口述/语音**：转写原文直接进 Event 正文，标 `source: voice`。
- **截图**（账单、体检、聊天记录、屏幕时间）：原件进 `attachments/YYYY/`，Event 留摘要 + 路径。
- **批量导出**（手环、银行 CSV、微信记录）：先转成 Markdown 一行一观测进 `metrics/`，
  原始文件留 `attachments/imports/`，并记一条 `type: event, slot: free` 说明来源与时间范围。
- **别人的话**：进 `learned`，必须带 `source:` 与证据等级；未证实的标 `verified: false`。

## 隐私分级（写死在协议里）

- 缺省 `priv: private`：进本地私有 git。**备份的前提是它在你自己的私有仓库里**，
  public 远端与 `priv != private` 冲突时，先修远端。
- 默认降为 `secret`（绝不进版本库）：可识别的第三方身份信息、性、精神或传染病诊断、
  身份证件与账号、精确住址、雇主未公开的敏感内部信息。其他健康趋势数字（睡眠、体重、体脂、支出）
  默认 `private`，用户可显式升级。
- **位置规则**：`secret/` 目录整体被 .gitignore 排除；散落在 inbox 里的 `priv: secret` 块不会被自动排除。
  所以 secret 内容只写在 `secret/` 下，其它地方留 `refs: ["[[sec-NNN]]"]` 指针 + 一句非敏感描述。
- 用户可以随时升/降级，AI 不劝阻、不解释、不评论。
- 记录不等于同意发布：任何 private/public 内容被用于对外产出前，必须逐条单独确认。

## 反羞耻条款

- inbox 是永久私密区。AI 在归档时**不得**加入评价性语言（"你应该…""这不健康"）。
- 不做 streak、不做打卡焦虑。中断 5 天回来时，第一句是"从哪一天开始补都行"，不是"你断了 5 天"。
- 补录用 `date` 字段写实际发生日期，`recorded: 今天` 分开记，避免污染时间线。

## 冷启动时间表（防止一上来搭大系统）

| 周 | 允许写入 | 不允许 |
|---|---|---|
| 1-2 | 只有 `inbox/` | decisions / beliefs / reviews 全部禁止 |
| 3 | 加 `metrics/`（≤3 个指标） | beliefs |
| 4 | 加 `decisions/` | 索引、向量、插件、自动化脚本 |
| 8 | 加 `beliefs/`、第一次周/月复盘 | 迁移工具、云端同步 |
| 12+ | 建 `packs/self/`、装第一个外部包、可选 SQLite FTS 索引 | — |

第 12 周之前主动提议引入数据库/向量/RAG 工具的，视为违反本协议。
理由：语料不足 200 条时，检索层的收益小于维护成本，且会让用户误以为"搭好系统=开始沉淀"。
