# 内核 · 多智能体协作流水线

> 这条只管结构：一件事从「想法」走到「人确认」，中间谁拿锁、谁写方案、谁执行、卡在哪。
> 不含某个人的偏好，也不绑定某个工具。

---

## 1. 五段状态机

**一句话**：思路不是任务，任务不是决策，各自有各自的状态，不许混成一张表。

| 段 | 载体 | 谁推进 | 状态 |
|---|---|---|---|
| 思路 | `idea` | 人写，agent 认领 | `open → planning → planned → executing → review → accepted`（失败分支 `needs_info`） |
| 方案 | `plan`（思路的子表，带版本） | 认领思路的 agent | `active / superseded` |
| 执行 | `task`（可拆多张，挂 `idea_id`、`plan_id`、`step_no`） | 任意 agent 抢 | `pending / running / blocked / done / failed / cancelled` |
| 决策 | `decision`（可挂 task 或 idea，带推荐与方向） | agent 写，人答 | `pending / answered / cancelled` |
| 确认 | 思路上的 `confirmed_by / confirm_note` | 人 | `accepted / needs_info` |

**怎么用**：能直接干的，跳过思路直接开卡；要拆解的，先思路后任务。
一张卡只能挂一个思路，一个思路可以有多版方案，只有 `active` 那版生效。

**失效条件**：一次性、五分钟能做完的事不需要走五段，直接做。

---

## 2. 一段只有一个 owner

**一句话**：同一时刻，一个执行单元只能有一个 agent 持有租约。

**怎么用**：抢用 `for update skip locked`，写 `owner + lease_until`；干活期间定期续租；
租约过期由回收器退回或判失败。推理过程不落库，落库的只有「谁、什么时候、拿走哪一段」。

**失效条件**：纯并行、互不写同一份产物的任务可以各自开卡，不必强行串行。

---

## 3. 亲和度优先于绝对优先级

**一句话**：先让 agent 接着做自己上次的项目，再谈谁的号小。

**怎么用**：取卡时排序为 `(项目 == 该 agent 上次项目) desc, priority asc, id asc`。
理由是切换项目的隐性成本（重新读上下文、重新建心智模型）常比优先级差更大。
要退回纯优先级，显式关闭亲和度。

**失效条件**：某项目长期没人接、或亲和度让高优任务饿死时，关掉亲和度，或给高优任务单独开一条队列。

---

## 4. 决策是接力，不是对话

**一句话**：agent 不会守着数据库等回答；它写完决策就结束这一轮。

**怎么用**：卡住 → 写 `decision`（问题、选项、推荐、方向）→ 任务置 `blocked` → 本轮结束。
人答完 → 决策 `answered` → 任务回 `pending` → 下一轮谁抢到谁接着干。
答案要写进事件流水，下一轮的 agent 从事件里读到，而不是靠上一轮的对话记忆。

**失效条件**：需要秒级响应、或需要多轮追问的，别用接力，改成常驻会话。

---

## 5. 完成与人确认是两件事

**一句话**：`done` 是执行者说的，`accepted` 是人说的，两者不能互相代替。

**怎么用**：`done` 必须带证据（验收清单逐条 PASS + 提交哈希或产出路径）。
所有执行卡清空后，思路自动进 `review`；人在页面上确认 `accepted`，或写补充退回 `needs_info`。
退回时不清空历史，方案升版本，旧版标 `superseded`。

**失效条件**：纯内部、无外部影响的小改动可以让执行者直接结，不设人确认。

---

## 6. 页面写库 ≠ AI 立刻动

**一句话**：agent 是被唤醒的，不是守着数据库的；页面写入和它开始干活之间有一个认领周期。

**怎么用**：默认接受「最多等一个心跳周期」。要秒级，就在写入后再触发一次唤醒，
但别把「已写入」当成「已开始」，更别当成「已完成」。

**失效条件**：有事件推送通道时，这条可以收紧到秒级。

---

## 7. 统一流程：四段流转（思路 → 决策 → 任务 → 检查表）

**一句话**：库是唯一真相，聊天不算；四段各有自己的落库判据，没落库的那段等于没发生。

**证据等级**：B（2026-11-11 一次积压复盘的自述记录：两个执行方在需要拍板时只在对话里说一句，
七张卡在等待队列里躺了约 15 小时。这是复盘叙事，不是埋点实测）。
**推翻条件**：若连续四周巡检显示「没落库、事后仍被正确处理」的比例过半，说明对话本身够用，
这条的强制力降级为提醒。

**与第 1 节的关系**：四段是五段状态机的执行面——思路落 `idea`，决策落 `decision`，
任务落 `task`，检查表对应人验收那一环（状态机里的确认）。方案仍按版本挂在思路上。

### 7.1 四段与「算完」判据

| 段 | 谁写 | 落到哪 | 什么时候算完 |
|---|---|---|---|
| 思路 | 提需求的人 | `coord_idea` | 有 plan，且 plan 已拆成卡 |
| 决策 | 执行方提，账号主拍 | `coord_decision` | `state=answered` 且 `answer` 非空 |
| 任务 | 拆解的人 | `coord_task` | `state=done` 且有回执路径 |
| 检查表 | 执行方 | `coord_delivery` | `verified_at` 非空 |

表名是逻辑名。实际 DDL、视图与 CLI 住在执行方仓库，不进内核——内核零依赖、不含数据库，
这里只规定字段语义与「算完」的判据。

### 7.2 四条铁律

1. **要人拍板的事，当场写成决策**：不许自己拍板，也不许只留在对话里。写完就是 `pending`，等账号主。
   **没写进库 = 没提过**，它会被忘掉。
2. **任务必须有 brief 路径和验收命令**：缺任何一个就置 `blocked`，不许凭标题开工。
3. **交付必须带检查表**：改了什么、怎么验、期望输出。验收由账号主或上级跑，执行方自述不算。
4. **一个项目一个执行方，不跨项目抢活**：归属表由执行方仓库维护，内核只规定「不抢」这一条。

每段结束都要落库：想法 → 决策 → 卡 → 回执。只活在对话里的一律视为没发生。

### 7.3 写库与巡检各只有一个入口

任何执行方、任何工作目录，写库只走一条命令：

```bash
node <执行方仓库>/coord-write.mjs <decision|task|delivery|list> --project <项目> ...
```

入口路径登记在执行方仓库的 `AGENTS.md`；内核只要求三件事：子命令固定、参数命名固定、
缺库时非 0 退出并说清原因。这份实现不随内核发布（它连数据库，违反「零运行时依赖」）。

巡检同理：`coord-sweep.mjs` 一次列出「想法没拆解 / 决策没过 / 任务没开工 / 交付没验收」四类积压，
口径固定、实现外置。**判据**：四类积压里任何一类连续两天非空，就当流程断了处理，不当繁忙处理。

**失效条件**：一次性、五分钟能做完的事，做完并落一条回执即可，不必走四段；
纯本地、无外部影响的小改动，验收可以由执行方按检查表自己结。
